# Strategy specification (PRE-REGISTERED, do not modify)

## Setup (previous-day daily candle structure)

- Compute previous trading day daily OHLC on USDJPY.
- Bearish setup: `open` in top 20% of prev-day daily range AND `close` in bottom 80%.
- Bullish setup: `open` in bottom 20% of prev-day daily range AND `close` in top 80%.

## Entry (next trading day, intraday on M5)

- Bearish setup: SHORT triggers when intraday price first **penetrates** prev-day low by `penetration_tick` ticks downward, then **reverts back through prev-day low** (close of an M5 bar at or above prev-day low after the penetration).
- Bullish setup: LONG triggers symmetrically (penetrate prev-day high by N ticks then revert below prev-day high).
- **First trigger of the day only** (one trade per setup-day per pair). If trigger never fires, no trade.

## Exit

- Stop loss: setup candle's opposite extreme ± 5 pip (ATR-static).
- Profit target: a **trailing stop** anchored at `(prev-day range × trailing_fraction)` from current best price, OR a **fixed-time** session-end exit.
- Time stop: depending on `session_boundary` cell, force-close at NY close (21:00 UTC) / London close (16:00 UTC) / 24h (next setup window).

## Filters / regime exclusions

- **Intervention dates excluded** — same 8-event list as S1 (look up from `wiki/learning/global-retail-fx-edges-2026-05-03.md` or fail loudly if list missing).
- **Intervention zone OFF**: when USDJPY > 158.000, the strategy is gated OFF for that day.
- No HMM gate. No MA gate. No additional filters beyond intervention exclusion. Adding filters mid-task = pre-reg violation.

# Sensitivity grid (Bonferroni m=27, PRE-REGISTERED)

| Axis | Levels |
|---|---|
| `penetration_tick` | 5 / 10 / 15 (USDJPY tick = 0.001) |
| `exit_method` | 50% trailing / 100% trailing / fixed-time (session-end only) |
| `session_boundary` | NY close (21:00 UTC) / London close (16:00 UTC) / 24h |

Total cells = 27. **Pre-registered primary cell = `(10, 50% trailing, NY close)`** — Connors & Raschke original.

Bonferroni denominator m = **27** (locked). Adjusted alpha = α / 27 where α=0.05 default.

# Verdict matrix v1 — all 7 axes per cell

For every cell (and especially the primary), report:

| Axis | Threshold tier (B-marg / B / A) |
|---|---|
| 1. N (executed trades) | ≥50 / ≥100 / ≥200 |
| 2. Wilson 95% lo (WR) | >0.40 / >0.42 / >0.45 |
| 3. PF | >1.0 / >1.2 / >1.5 |
| 4. OOS PF / IS PF (50/50 walk-forward, time-ordered) | >0.4 / >0.6 / >0.8 |
| 5. Bonferroni-adjusted p (m=27, one-sided WR > BEV_WR_USDJPY=34.4%) | <0.20 / <0.10 / <0.01 |
| 6. Sharpe (annualized, daily PnL) | >0.0 / >0.5 / >1.0 |
| 7. Kelly fraction | >0 / >0.05 / >0.10 |

A cell qualifies for a tier only if **all 7 axes** meet that tier's threshold.

Emit a **per-cell verdict** (B-marg / B / A / FAIL) and an **overall Scenario verdict**:

- **Scenario A** = primary cell ≥ B AND null bootstrap p < 0.05 AND |corr(fib_reversal, S4)| < 0.3 → Shadow promote candidate. Write LOCKED `pre-registration.md`.
- **Scenario B** = primary cell == B-marginal only (or other cells > B but primary < B) → hold. Recommend Wave 4 sensitivity expansion.
- **Scenario C** = primary cell FAIL OR null bootstrap p ≥ 0.05 OR fib_reversal |corr| ≥ 0.5 → Reject. Recommend catalog §B-2 → "academic only".

If results land between scenarios, default to the **stricter** verdict (A→B→C) and document why.

# Validity checks (REQUIRED, all must run)

## 1. Null bootstrap (primary cell only)

- Shuffle setup labels (bullish/bearish/none) randomly across all setup-eligible days, 1000 iterations.
- For each shuffle, compute primary-cell PF.
- Report: empirical PF percentile vs null distribution, two-sided p, distribution mean/median.
- Pass = empirical PF > 95th percentile of null.

## 2. fib_reversal correlation

- Pull `fib_reversal` LIVE-comparable PnL series (is_shadow=0 only — `feedback_live_shadow_separation`) from Render API for the most recent **available LIVE window** (likely <12 years; document the actual window).
- Re-simulate S4 primary cell over the same window for apples-to-apples.
- Compute rolling 30-day Pearson correlation of daily PnL.
- Report: median rolling corr, IQR, fraction of windows with |corr| > 0.5.
- Decision rule: median |corr| < 0.3 → portfolio additive. ≥ 0.5 → too redundant; merge or pick one.

## 3. Time-cohort integrity

- Annual PnL by year (2014..2026), monthly PnL heatmap, regime concentration check (no single year > 50% of total PnL; flag if violated, ref `feedback_cohort_time_check`).

## 4. Broker cross-check

- Re-run primary cell on yfinance `USDJPY=X` daily-derived M5 surrogate (the closest yfinance can provide; if M5 is not available, document and use the highest-frequency yfinance data and run a comparable-day-bias subset).
- Report PF and N delta vs primary cell. ≥ 30% PF deviation = broker artifact suspect.

## 5. Live/Shadow separation guard

- The fib_reversal correlation step pulls Live data. **Use Render API as the source of truth**, not local DB (`feedback_check_orphan_local_app`).
- Before pulling LIVE data, run `pgrep -f app.py` and report any orphan local processes that could pollute caches. If any are found, abort the LIVE-correlation step and report; do not silently ignore.
- Filter `is_shadow=0` strictly when computing fib_reversal PnL.
