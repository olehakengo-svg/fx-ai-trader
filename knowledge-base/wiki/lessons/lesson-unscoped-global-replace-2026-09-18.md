# lesson: スコープを絞らない全文置換が、無関係な過去の記録を静かに改竄した

**発見日**: 2026-09-18 | **rule**: R3 (構造バグ) | **PR**: #270 第12波 | **自己申告**

## 何が起きたか

PR #270 のレビュー対応 (第11波) で、検出力曲線の数値を再計算した結果に合わせて
KB の記述を更新する必要があった。10 組の新旧ペアを列挙し、**4 つの KB ファイル全体**に
対して素朴な文字列置換を一括で当てた:

```python
NEW = [("0.132","0.130"), ("86.8%","87.0%"), ("+0.282","+0.281"), ("0.735","0.727"),
       ("26.5%","27.3%"), ("0.958","0.953"), ("+0.494","+0.496"), ("4.2%","4.7%"),
       ("+0.074","+0.075"), ("+0.694","+0.693")]
```

うち 2 組が**別の数値の部分文字列**として他所に食い込んだ:

| 置換意図 | 巻き込まれた記録 | 結果 |
|---|---|---|
| 検出力 `0.132` → `0.130` | family A **Gate A の実測値 `0.1327`** (147/1,108 bd) | `0.1307` に改竄 (pre-reg §10.3 表 / 台帳 #27 / changelog の 3 箇所) |
| 検出力表の `4.2%` → `4.7%` | 2026-08-07 の **SL_HIT ラベル衝突の実測 `54.2%`** (WIN 1792/3308) | `54.7%` に改竄 (changelog の 2 箇所) |

**pre-reg の凍結表と、1 ヶ月半前の無関係な本番実測**という、
このレビュー波が触れてよい範囲の外にある記録が壊れた。

## なぜ静かに壊れたか

1. **置換は成功する** — 部分文字列マッチは例外を出さない。`sed`/`str.replace` に
   「意図した箇所だけ」という概念が無い
2. **CI も pre-commit も通る** — 数値の整合性を検査する仕組みが無かった。
   Markdown の中の数字は誰にも検算されない
3. **差分が巨大で埋もれた** — 同一コミットで意図的に 30 箇所以上の数値を動かしており、
   意図した変更の海に意図しない 5 箇所が紛れた
4. **自分の目視レビューを通過した** — `git show --stat` は見たが、
   変更**トークン**を一つずつ検算はしなかった

捕捉したのは **Codex connector のレビュー** (「Restore the actual Gate A fraction」
「Keep the SL_HIT percentage consistent with its counts」)。
つまり**自分では見つけられず、外部レビューが無ければ main に入っていた**。

## 修正

- 5 箇所を復旧。置換ではなく**分子・分母からの再計算**で真値を確定
  (147/1108 = 0.1327 / 1792/3308 = 54.2%)、置換は**行全体を文脈アンカーにした完全一致**で実施
- コミット全体を `--word-diff` で**トークン単位に分解し、10 組全ての波及を全数照合**
  (意図外は上記 5 箇所のみ、他 8 組は波及なしと確認)
- 再発防止 pin `tests/test_kb_numeric_consistency.py` を新設 —
  **性質ベース** (語句 grep ではない): 「**割合の主張は、その場に書かれた分子・分母と一致する**」
  「**件数を伴わない引用は、件数付きの正本と一致する**」。
  破損コミット (`3bec6df3`) の内容に対して 3 本とも落ちることを counterfactual で確認済み

## 教訓

- **KB への一括置換は、スコープを「ファイル」ではなく「行」に絞れ。**
  数値の置換は必ず**前後の文脈を含めた完全一致**で行い、出現回数を事前に表明して
  期待と一致しなければ中止する (`count() != expected` で abort)
- **数値の部分文字列は必ず他の数値に埋まっている** — `0.132` は `0.1327` の中に、
  `4.2%` は `54.2%` の中にいる。短い数値リテラルほど危険
- **自分が触ってよい範囲を超えた差分が出たら、それはバグである。**
  レビュー対応は「指摘された箇所」だけを動かす。1 ヶ月半前の実測値が動いたなら、
  それは対応ではなく事故
- **数値主張には算術の pin を置ける** — 「a/b = p」と書いてある限り、
  文言がどう変わっても検算できる。文言 grep の pin は誤爆するが、算術の pin は誤爆しない
  ([[lesson-validity-check-pins-proxy-2026-09-02]])
- 本件は**凍結文書 (pre-reg) の改竄**でもあった。凍結の意味は「後から動かさない」ことなので、
  事故であっても改竄は改竄。**凍結文書は置換スクリプトの対象に含めない**のが正しい運用
