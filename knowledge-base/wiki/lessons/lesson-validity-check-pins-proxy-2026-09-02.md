# 教訓: 妥当性チェックは「性質」を pin せよ、「時変の代理」を pin するな (2026-09-02)

**種別**: 統計ハーネスの設計欠陥 / **発見**: alpha_scan 静的ブロック再較正 pre-reg の P0
**関連**: [[alpha-scan-static-block-recalibration-prereg-2026-09-02]] §7 /
MEMORY `project_freshness_ui_ssot_pin_property_2026_08_29` (構造 pin の同型教訓)

## 何が起きたか

本番コードの 10 個の静的ブロック条件を行データから再構成して再較正する pre-reg で、
「再構成が正しいか」を検証する妥当性チェック (P0) を観測前に凍結した。凍結した条件は:

> LIVE 行のうちブロック条件を満たすものは `_is_live_tier_exempt` セルにほぼ限られるはず。
> **exempt でないセルの LIVE 行が多数出るなら再構成が誤り** → 研究中止。

実測は **104 行**。字義どおりなら中止だった。

## 誤っていたのは再構成ではなくチェックの方だった

`_is_live_tier_exempt` = ELITE_LIVE ∪ PAIR_PROMOTED は **時変**である。
セルは demote されて出入りする。P0 は**現在の**ポートフォリオを静的集合として
ハードコードしており、当時 exempt だったセル (bb_rsi_reversion / session_time_bias /
vix_carry_unwind の承認済み Overlap pilot carve-out 等) を全て「違反」と数えていた。

違反行の月次分布が決定的だった:

| 月 | 違反 LIVE 行 / 全 LIVE 行 | 割合 |
|---|---|---|
| 2026-04 | 26 / 84 | 31.0% |
| 2026-05 | 10 / 54 | 18.5% |
| 2026-06 | 58 / 115 | 50.4% |
| 2026-07 | 10 / 27 | 37.0% |
| **2026-08** | **0 / 12** | **0.0%** |

基準率 ~35% で 12 行連続ヒットゼロは p≈0.006。違反セルの最終出現日は
全て当該セルの demote 時期と一致した (vix 07-30 / ny_close 07-08 / bb_rsi 07-02 …)。

## 何を pin すべきだったか

検証したかった**性質**は「再構成が engine の読み出し経路と一致するか」。
P0 が pin したのは「今日の exempt 集合に入っているか」という**代理**だった。

正しい検証は**コードの同一性**で行える (実際、これで解決した):

- `_regime_type_r = sig["regime"]["regime"]` (`demo_trader.py:5139`)
- 本ツール `_regime_type()` = `json.loads(row["regime"]).get("regime")`
- 読み戻し側 `demo_db.py:2135-2136` = 同一

三者一致を示せば、regime 依存の 3 ブロックの曖昧性は消える。
残る 7 ブロックは instrument/hour/direction のみで曖昧性ゼロ。

## 規律 (次回から)

1. **妥当性チェックは「実装と再構成が同じ読み出し経路か」をコードで示す形に書く。**
   データ側の分布で代理検証するのは補助であって主ではない
2. **代理を使うなら、その代理が時不変かを明示的に問う。**
   時変なら、観測窓と同時期のスナップショットを使うか、時系列で見る
3. **中止条件は「何が観測されたら中止か」でなく「どの前提が崩れたら中止か」で書く。**
   前者は前提が間違っていたときに正しい研究を殺す

## 同型再発の記録

PR #209 で「**構造 pin は性質を書け、構文を書くな**」を学んだ (ファイル全体への
リテラル一致 pin が ①等価リファクタで落ちる ②スコープ外の同構文で素通り の両方向に誤り)。
今回は同じ誤りが**統計の妥当性チェック側**で再発した = **通算 2 領域目**。
「pin/チェックの対象を性質でなく観測可能な代理で書く」は領域横断の失敗 mode である。
