# 教訓: 自分で組み立てた URL の 404 は「存在しない」の証拠ではない (2026-08-31)

- **rule**: R3
- **実例**: [[mof-monthly-total-verdict-2026-08-31]] / 誤った側: [[mof-monthly-total-check-2026-08-28]] §3

## 何が起きたか

MoF 月次介入額の公表チェックで、過去 12 窓のページ名がたまたま全て月末営業日だったことから
**命名規則を「月末営業日」と推定**し、`20260831.html` を直接叩いた。404 が返ったので
「未公表」と結論し、deadline を再武装した。

実際の公表は **`20260828.html`** (2026-08-28 公表、**15兆3,993億円** = 保有データ中の単一窓最大)。
正しい命名規則は **`window_end + 2〜4 日`** で、月末営業日との一致は偶然だった。

## 教訓 1 — 列挙できるものを推測するな

> **構築した URL の 404 は「未公表」を意味しない。「自分が予測した名前ではない」しか意味しない。**

索引 (`index.html`) が存在するなら、**索引を列挙する**。命名規則の推定は
「N 個のサンプルに合う規則」を作る作業であり、N+1 個目で破れる。しかも破れたとき
返ってくるのは**例外ではなく 404** = 正常な「無い」と区別がつかない。

- 既存の `tools/mof_interventions_fetch.py` は**正しく index を列挙していた**。
  欠陥は「ツールがない」ことではなく、**人手チェックがそのツールを迂回した**こと
- 一般化: 外部リソースの存在確認で「404 = 不在」と読めるのは、**その URL が
  自分の推定ではなく相手の索引/API から得たもの**のときだけ

## 教訓 2 — 「収集した」と「読まれた」は別物 (write-only 6 例目)

同じ事象に**独立した第 2 の欠陥**があった。日次 cron は index を正しく列挙して
**08-29 にこの値を CSV へ書き込み済み**だった。しかし**その CSV を読む検知器が無く**、
値は 2 日間リポジトリに座ったまま誰も気付かなかった。

registry のエントリは `deadline_info` 型 = **期日まで何も評価しない**。宣言された
到達経路も「Claude が公表ページを確認」= 教訓 1 の人手経路だった。

> **データを収集する経路を足したら、それを読む経路を同じコミットで足す。**
> 「収集済み」は「監視済み」ではない。

同型の既出: PR #207 (`no_rows` vs `error`) / PR #208 (検知器の call-site 欠落) /
PR #210 (API 到達不能の無検知)。

## 教訓 3 — pin は失敗 mode を固定してしまうことがある

旧テストは `type == "deadline_info"` かつ `deadline == "2026-08-31"` を assert していた。
これは**「期日待ち + 人手 URL 推測」という誤った設計そのものを凍結**しており、
設計を直そうとすると**テストが抵抗する**状態だった。

> **構文でなく性質を pin せよ。** 置換後は「後継エントリが機械評価可能な型であること」
> +「収集済み CSV を実際に読む経路であること」を pin している。

## 教訓 4 — counterfactual が初回に通ったら「安全」でなく「pin が無い」(3 度目)

修復時の counterfactual 3 本のうち、**② (`read_csv_rows` がファイル欠落を `[]` に折り畳む)
が初回素通りした**。evaluate 側で `None` と `[]` を分離しても、**fetcher 側で折り畳んだら
意味がない**のに、fetcher 単体の pin が無かった。

PR #208 の ⑥、PR #210 の ⑧⑨ に続き **3 度目**。counterfactual は「落ちること」まで
実測して初めて pin として成立する。

## 適用チェックリスト

外部一次情報の存在確認を書くとき:
1. 索引/API があるか？ あるなら**列挙**する。URL を組み立てない
2. 組み立てざるを得ないなら、**404 を「不明」として扱う** (「不在」と断定しない)
3. 収集経路を足したら、**同じコミットで読み手を足す**
4. pin は「性質」で書く。判定の型・閾値・URL 文字列を凍結しない
5. counterfactual は**落ちるまで実測**する
