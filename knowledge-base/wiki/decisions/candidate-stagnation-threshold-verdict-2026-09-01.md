## 判定

**閾値 `CANDIDATE_STAGNATION_HOURS = 6` を据え置く。** 変更しない。

2026-08-27 以来の暫定値 (バースト実効 **N=16** / 10 時間窓) を、
**90 日 / 書込みタイムスタンプ 274,862 / floor 30 分以上のギャップ 130 本**の

### その 1 回は誤発火ではなく**真の検知**だった

```
2026-08-21 21:59:57 → 2026-08-26 03:39:56
```

これは **Disk 満杯事故 (2026-08-21〜08-25、全 SQLite 書込みが 3.5 日停止)** そのもの。
`modules/freshness_policy.py` の docstring が「**ダッシュボードには何の異常も出なかった**」

→ **閾値 6h は、この一連の監視作業を生んだ当の事故を検知できる**。かつ
**90 日で誤発火ゼロ**。

## 構造 — 予測は的中した

PR #213 で「構造的な最大ギャップは日次 2h ではなく**週次 3h**」とコードから予測した。
実測はこれを厳密に確認した:

- 上位 13 本のうち **12 本が金曜→月曜の週次再開ギャップ**で、
  **市場オープン換算 3.000〜3.736 h** (実時間 50.00〜51.74 h) に密集
- 残る 1 本が上記の事故

ばらつきの出所は境界ではなく**金曜最終候補行の時刻**だった (実測 20:16 / 20:46 /
20:58 / 20:59 / 21:02 / 21:59 UTC)。境界の合成値 3.00h が下限で、最終行が早い週ほど
上に伸びて最大 3.736h になる。

## 閾値が妥当な理由 — 分布に**広い空白帯**がある

```
構造的な最大 (週次)      3.736 h
        ↑
     空白帯 (観測ゼロ)          ← 閾値 6.0 はこの中にある
        ↓
   事故 (真の異常)         54.666 h
```

**3.736h と 54.666h の間に観測がまったく無い。** この帯のどこに閾値を置いても
90 日の判定結果は同一 (誤発火 0 / 真検知 1) になる。したがって 6h は
knife-edge ではなく、広い平坦域の内側にある。

- 構造的最大に対する余裕: **6.0 / 3.736 = 1.61 倍**
- ⚠️ 2026-08-27 の根拠記述「max 120.3 分の **3 倍**」は**誤り**だった。日次 2h
  ブロックだけを見て**週次再開ギャップ (3.0〜3.7h) を見落としていた**。真の余裕は
  3 倍ではなく **1.61 倍**。ただし上記の空白帯があるため、**結論 (6h 据え置き) は
  変わらない** — 根拠の方を訂正する

## 動かさなかったもの (意図的)

- **閾値**: 据え置き。下げる根拠は無く (余裕 1.61x は空白帯に守られている)、
  上げる根拠も無い (誤発火ゼロ)
- **週末境界の 1 時間ずれ** (`freshness_policy` 金 21:00 / `demo_trader` 金 22:00):
  この 1h は週次ギャップ 3.00h に直接乗っているが、空白帯が広いため判定に影響しない。
  **統一は別途の判断**とし、本件では触らない (実測で害が出ていないものを動かさない)
