## 2. 判定 — user の「7月の負けは介入をくらった」説

**7月のうち 07-01〜07-29 については反証された。**

月次総額 **0円** は「窓内のどの日にも介入が無かった」を意味する。総額 >0 が
「窓内のどこかに介入があった」までしか言えない (日次帰属は Q3 開示 ~11月) のと
**非対称で、ゼロの側が遥かに強い情報**である — 個別日を特定せずに窓内の全日を
一括で否定できる。したがって 07-29 までの損失に介入は**寄与し得ない**。

**ただし最重要の 2 日は未決着**。user 外部口座のワースト日 07-30 (−69,628円、
レンジ 579p) / 07-31 (−21,370円、370p) は**次の窓 (07-30〜08-27) に落ちる**。
この窓の公表は 404 で未着。

## 3. 公表日の訂正 — registry は「~08-29」としていたが実際は月末営業日

過去 12 窓のページ名 (= 公表日) は全て `2026 07-31 / 06-30 / 05-29 / 04-30 /
03-31 / 02-27 / 01-30 …` = **各月の最終営業日**。窓の締め (~27-29日) の
2〜4 日後にあたる。したがって 07-30〜08-27 窓の公表は **2026-08-31 (月)** が
最有力で、08-28 (金) 時点で未着は**正常**であり異常ではない。

→ registry を resolve せず **deadline を 2026-08-31 に再武装**した。

## 4. T5 復帰第2要件への含意

第2要件 (介入観測 or 当局の 160 防衛言及) の認定材料としては、本開示は
**否定側の材料**。0円 = 06-29〜07-29 に介入なし。
`t5-jpy-cap-restore-price` は第1要件のみ点灯のまま、**lot 0.5x 維持**で変更なし。

⚠️ cross-LOCK 注意 (MEMORY `project_t5_restore_mof_crosslock_2026_08_10`):
第2要件の認定は**外部一次情報のみ**。価格シグネチャからの介入日推定は
`mof-next-episode-reverdict` (#4) の 2026 窓 OOS を burn するため引き続き禁止。
本チェックは公式開示の読み取りのみで、その禁止に抵触しない。

## ⚠️ 2026-08-31 追記 — §3 の推論は誤りだった

本ページ §3 は「公表日は月末営業日」と結論し `20260831.html` を待った。**これは誤り。**

実際の当該窓ページは **`20260828.html`** (令和8年7月30日〜**8月26日**、公表 2026-08-28、
**15兆3,993億円**)。正しい命名規則は **`window_end + 2〜4 日`** であり、過去 12 窓が
月末営業日に見えたのは偶然の一致だった。

**構築した URL の 404 は「未公表」の証拠ではない** — 「自分が予測した名前ではない」しか
意味しない。§5 に書いた `index.html` の列挙を実際に行っていれば当日中に判明していた。

さらに、日次 cron は **08-29 にこの値を既に収集していた** (write-only 6 例目)。
