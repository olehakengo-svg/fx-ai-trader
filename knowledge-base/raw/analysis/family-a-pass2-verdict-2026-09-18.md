## 2. 検出力 — 🔴 **初版の「検出力不足ではない」は撤回する**

初版は positive control (ほぼ完全な検出器 J=0.87 が p=0.019 で通る) をもって
「本 FAIL は検出力不足ではない / 測って分離が無かった」と断定した。**これは誤りである**
(Codex P2 / PR #270)。**ほぼ完全な効果が検出できることは、現実的な効果量に対する
検出力の証拠にならない。**

そこで **post-hoc の検出力曲線**を実測した (実 armed 系列 147/1,108 bd + **合成ラベル**、
各 **600 本の受理 draw** (棄却分は再抽選して必ず 600 本集める)、seed 20260918。実ラベルは再使用していない)。
効果量の軸は **armed 窓に掛かる episode block 数** — 実ラベルは営業日系列上で
**[3, 1, 2, 1] 日の 4 block** に集中しており、7 陽性を一様ランダムに散らすと
**実際より独立な試行を仮定して検出力を過大評価する**。

| armed 窓に掛かる **episode block** | 想定 J | **検出力 (p ≤ 0.05)** | 取り逃す確率 |
|---:|---:|---:|---:|
| 0/4 | −0.134 | 0.000 | 100% |
| 1/4 | +0.075 | 0.000 | 100% |
| **2/4 (= 観測値)** | **+0.281** | **0.130** | **87.0%** |
| 3/4 | +0.496 | 0.727 | 27.3% |
| 4/4 (全 block が hit) | +0.693 | 0.953 | 4.7% |

> **hit の定義** = その block の**いずれかの日**が armed 窓に入ること (検出器の event 意味論と一致)。
> **miss = その block の全日が非 armed**。両者は生成位置の**全日を検査して強制**している。
> さらに配置は **episode-gap (30 暦日 ≈ 21 営業日) の近傍を棄却**し、完成サンプルを
> `episode_blocks` にかけ直して **4 block のままであることを検証**している
> (これを怠ると生成ラベルが 4 未満の episode に潰れ、4-block 設計の曲線にならない — Codex P2 第7波)。
> ⚠️ **4/4 は「block 基準の完全」であって day 基準の完全ではない**。

⇒ **観測された効果量 (2/4 block、J=0.282) における検出力は 0.130 しかない。**
仮にその効果が実在しても **87.0% の確率で取り逃す**設計だった。
検出力が慣例的な 0.9 に達するのは **全 4 block が hit する場合のみ**である。

### 2.1 したがって本 FAIL が意味すること / 意味しないこと

- ✅ **意味する**: 凍結された α 規則を満たさなかった。**PASS の要件は満たしていない。**
- ⚖️ **弱い証拠になる**: 全 block hit 級 (J≈0.70) の対立仮説に対しては
  **シミュレーション上の感度が 0.953 と高い**ため、それが真なら検出されていた公算が大きい。
  ただし **その効果が真でも 4.7% は非有意になる**ので、これは
  **「そのレベルの効果が無い」ことの証明ではない** (Codex P2 第7波)。
  不在を主張するには **同等性/非劣性検定か、当該効果量を除外する信頼区間**が要る。
  本 pre-reg はどちらも規定していないので、**不在の主張はしない**。
- ❌ **意味しない**: 「分離が無い」「検出器に情報が無い」。
  **観測値は検出力 0.130 の領域にあり、sampling noise で容易に説明がつく。**
  3/4 block (J≈0.49) ですら検出力 0.727 で、約 4 分の 1 を取り逃す。
- ❌ **意味しない**: 「検出力不足ではない」。初版のこの断定は**撤回する**。

> **凍結時に power analysis を規定しなかったこと自体が設計の不足だった。**
> §5 で「有効 N = 4 episode blocks、いかなる結果も記述級」とは書いたが、
> **記述級と宣言することと、どの効果量なら検出できるかを事前に数値化することは別物**である。
> 事前に測っていれば「**実用域に入るのは全 block hit のときだけ**」と分かり、
> 凍結前に設計を見直せた。本曲線は post-hoc であり、**verdict の判定には一切使っていない**
> (FAIL は凍結規則のまま)。次の pre-reg では**凍結時に block 構造を保存した検出力曲線を
> 計算し、実用域に入る効果量を宣言する**こと。

⚠️ §3 のカレンダー欠陥 (陽性 10 → 7) は**この検出力をさらに削っている**。
削る前の陽性 10 での再計算は 2 度目の look にあたるため**行わない**。

## 3.1 🔴 凍結仕様の欠陥 ②: null が 4 block を厳密には保たない

凍結 null は「**ラベル系列の episode-block circular-shift (block 構造を保ったまま一様シフト)**」
(§5)。実装はこの操作をそのとおり行っている。しかし **営業日 index 上で一様にずらしても、
episode 規約が暦日ベース (gap ≥ 30 暦日) であるため block 構造は厳密には保たれない** —
span 20 営業日の block (2022-09-22 … 10-24) が祝日の多い区間に落ちると 2 episode に割れる。

実測 (signal 非参照の構造診断、J も p も計算していない):

| シフト後の block 数 | 本数 |
|---:|---:|
| 4 (= 観測と同じ) | 882 |
| **5 (割れた)** | **225** |
| 計 | 1,107 |

⇒ **null の 20.3% は 4 block ではなく 5 block の配置**であり、
`p=0.1074` はその混合の上で計算されている。

### 直さない — そして直さない理由

**§10.5 は凍結後の統計設計変更を禁止している。** null を変えれば p が変わる =
**凍結された primary の作り替え**であり、これは §3 のカレンダー欠陥を直さなかったのと
同じ理由で拒否する。「直したら通るかもしれない」は、まさに pre-reg が防ぐために
存在する誘惑である。

- **バイアスの向きは判定不能** — 5 block の配置は陽性がより散る方向だが、
  それが null 分布の裾を太くするか細くするかは**再計算しないと言えない**。
  そして再計算は 2 度目の look にあたる。
- **verdict は FAIL のまま確定**。本節は限界の開示であって再解析ではない。
- **再挑戦は新規 pre-reg のみ**。そこでは null を
  **暦日座標で block を動かす**か、**4 block を保たないシフトを棄却する**形で明示的に規定する。

> 凍結仕様の欠陥はこれで 2 件目 (§3 のラベル側カレンダー、本節の null 構造)。
> どちらも **「凍結文の意図」と「凍結文が指定する操作」がズレていた**という同じ形で、
> 凍結前に**操作を実データ上で 1 回走らせて性質を確認していれば**両方とも見つかった。

## 7. forward OOS の扱い

**凍結された FAIL 分岐により、§6 の forward OOS 手続きは停止する。** これは
pre-reg が事前に決めた帰結であって、新たな推論ではない。

🔴 **初版はここで「forward で確認すべき仮説がない = 実質無意味化」と書いていた。撤回する**
(Codex P2 第11波)。§2 で「観測効果量での検出力は 0.130、非有意は分離の不在を示さない」と
書いた直後に、**その非有意を根拠に仮説そのものを無意味と宣言していた** — §2.1 で退けたのと
同型の推論誤りである。**87.0% の確率で取り逃す設計の結果は、仮説の無意味さを支持しない。**

正しい言い方:

- ✅ **凍結手続きとしての forward OOS は停止する** (§5 FAIL 分岐の事前規定)
- ❌ **仮説が無意味になったわけではない** — 「発言ラダーが介入確率に情報を持つか」は
  **本検定では判別できなかった**だけであり、より検出力のある設計なら答えが出る余地がある
- **forward 期 (2026-07-30〜) の gate×outcome 計算の禁止は解除しない** — 将来の新 pre-reg が
  同じ窓を genuine OOS として使える状態を保つため、**未接触のまま凍結**する。
  これは「仮説が死んだから放置する」のではなく「**次の検定のために窓を温存する**」措置である。
